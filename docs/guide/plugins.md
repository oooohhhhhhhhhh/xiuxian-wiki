# 插件开关

服务端的玩法被拆成 **30 个可独立启停的开关**：24 个稳定玩法模块、2 个实验性插件、
4 个消息通道适配器。全部开关集中在 `config/plugins.yml` 一个文件里。

::: tip 为什么要拆开关
想让服务器只跑"纯修仙"、不要社交和交易？关掉对应模块即可 ——
它的指令、REST 接口与后台定时任务会**一并失效**，不会留下半开半闭的状态。
:::

## 文件格式

```yaml
plugins:
  exploration: true            # 启用（默认）
  trade: false                 # 停用
  # sect: true                 # 注释掉 = 使用默认值 true
```

| 写法 | 含义 |
| --- | --- |
| `true` | 启用（默认） |
| `false` | 停用，**重启后生效** |
| 整行注释掉 | 等同于使用默认值 `true` |

## 取值优先级

```
config/plugins.yml          ← 最高
        ↓ 没有该键时
jar 内置的 plugins.yml 模板
        ↓ 还是没有时
旧配置只读兜底：application.yml 的 built_in_plugins.*
                config/experimental.yml 的 experimental.*
```

::: tip 从旧版本升级
旧版把开关写在 `application.yml` 的 `built_in_plugins` 段与 `config/experimental.yml` 里。
升级后首次启动会**自动迁移**到 `config/plugins.yml`；未被迁移到的键仍会读取，
但一旦 `plugins.yml` 里存在同名键，就以 `plugins.yml` 为准。

迁移完成后，旧的 `config/experimental.yml` 可以自行删除。
:::

### 实验性插件

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `experimental_sect_war` | ❌ **关闭** | 宗门战（实验性） |
| `experimental_energy_exchange` | ✅ 开启 | 能量转化/等价交换（实验性） |

::: warning 实验性插件默认值不一致
`experimental_sect_war` 默认**关闭**，`experimental_energy_exchange` 默认**开启**。
两者由旧 `config/experimental.yml` 的 `sect_war` / `energy_exchange` 迁移而来。

停用即整体关闭该实验性内容：相关指令/接口会被门控拒绝。
:::

### 消息通道适配器

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `onebot` | ✅ | OneBot WebSocket/截图 消息通道 |
| `qq` | ✅ | QQ 官方机器人消息通道 |
| `minecraft` | ✅ | Minecraft 内嵌服务器消息通道 |
| `minecraft-player` | ✅ | Minecraft 玩家直连消息通道 |

::: tip 类型级 vs 实例级
这四个是**类型级总开关**，关掉等于整类通道停用。

具体某个机器人实例（哪个地址、哪个端口、是否启用）由
`config/adapters.json` 控制，两者是"与"的关系 ——
类型开关为 `false` 时，实例配得再全也不会启动。

详见[消息通道与适配器](/dev/adapters)。
:::

::: warning 外部插件不受本文件控制
`plugins/*.jar` 形式的第三方插件，其开关由插件自身的启停状态管理。
:::

## 在 WebUI 里运行时启停

除了改文件，也可以在**管理后台 → 插件管理**页直接开关：

1. 登录管理后台（需要 `admin.plugins` 权限）
2. 进入「插件管理」
3. 切换开关 —— 选择会**持久化写回 `config/plugins.yml`**
4. 页面会提示是否需要重启才能完全生效

::: tip 在线启停的边界
运行时启停会立即改变**指令与接口的门控状态**（停用后相关指令立刻不可用）。
但如果该模块注册了后台定时任务，已启动的任务需要重启进程才会彻底停止。
:::

## 停用后会发生什么

| 受影响的东西 | 行为 |
| --- | --- |
| 玩家指令 | 指令注册表返回 `null`，玩家看到"功能未开放"类提示 |
| REST 接口 | 被 `ModuleGateFilter` 拦截 |
| WebSocket action | 同样被门控拒绝 |
| 后台定时任务 | 不再执行（重启后彻底停止） |
| 数据库数据 | **不会删除**。重新启用后数据仍在 |

::: danger 停用不等于卸载
关掉模块只是让它不工作，**数据库里的相关数据会原样保留**。
如果之后重新启用，玩家的宗门、挂单、农田等都会回来。
:::
