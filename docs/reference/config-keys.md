# 配置项全表

本页是 `config/application.yml` 与 `config/plugins.yml` 的**逐项对照表**，
用于查阅配置键的名称、类型、默认值与作用。配置的使用方式与合并规则见
[配置详解](/guide/config)。

::: tip 默认值的含义
表中「默认值」一列取自 jar 内置的 `application.yml` 模板。
由于外部 `config/application.yml` 会**覆盖**内置模板（而不是替换），
升级后新增的配置键会自动继承模板里的默认值，**不需要你手工补齐**。
:::

### 2. HTTP 服务器 `server`

| 配置键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `server.host` | string | `127.0.0.1` | 监听地址。`0.0.0.0` 对外网开放，`127.0.0.1` 仅本机 |
| `server.port` | int | `8080` | HTTP 服务端口（管理后台 `/api/admin`、REST 接口） |

::: warning 默认只监听本机
模板默认值 `127.0.0.1` 表示**外网无法访问**。要让外部访问（例如远程玩家连接 REST 或管理后台），
需要改为 `0.0.0.0`，并自行做好反向代理与防火墙配置。
:::

::: danger 但安装向导会把 host 无条件写成 0.0.0.0
`InstallResource` 在保存安装配置时**不读表单里的 host，直接写死** `server.host = "0.0.0.0"`。
因此凡是通过 `/install` 向导完成安装的服务器，实际生效的监听地址都是 **`0.0.0.0`（监听所有网卡）**，
而不是模板里的 `127.0.0.1`。

装完之后请**手动检查并改回** `127.0.0.1`（或在防火墙/安全组上限制来源），否则服务端会直接暴露在公网。
:::

### 2b. 安全相关的启动检查

服务端在启动时会主动做两项安全检查：

| 检查 | 触发条件 | 行为 |
| --- | --- | --- |
| 绑定公网 + 默认管理员密码 | `server.host` 不是 `127.0.0.1`/`localhost`/`::1`，且管理员凭据仍为空或 `admin123` | 打印**严重安全警告** |
| JWT 密钥仍是自动生成的 | `JwtUtil.init` 走的是安装模式分支（`autoGenerated = true`） | `warnIfAutoGenerated()` 打印警告 |

### 4. JWT 签名密钥 `jwt`

| 配置键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `jwt.secret` | string | `""`（空） | 玩家 Token 签名密钥 |

`jwt.secret` 的行为分**三种情形**（实现见 `JwtUtil.init(boolean isInstallMode)`，`MIN_KEY_BYTES = 32`）：

| 情形 | 判定 | 结果 |
| --- | --- | --- |
| 已配置且足够长 | 非空白且字节数 ≥ 32 | 正常加载，`autoGenerated = false`，打印 `✓ JWT 密钥已从配置加载` |
| 已配置但太短 | 字节数 < 32 | **启动失败**：抛 `RuntimeException`，`Main` 捕获后 `System.exit(1)` |
| 留空 + **未安装** | `config/.installed` 不存在 | 生成 48 字节随机临时密钥，`autoGenerated = true`，打印 `⚠ 安装模式：已生成临时 JWT 密钥` |
| 留空 + **已安装** | `config/.installed` 存在 | **启动失败**：抛 `RuntimeException`，`Main` 捕获后 `System.exit(1)` |

::: danger 留空只有在「未安装」阶段才被容忍
注意：**不是"每次启动都会随机生成"**。安装向导阶段（`InstallResource.isInstalled()` 为 false）
才会生成临时密钥，此时重启确实会让已签发的 Token 全部失效；
而**已安装**的服务器把 `jwt.secret` 留空会**直接拒绝启动**，根本起不来。

生产环境请设为至少 32 字节（256 位）随机串：

```bash
openssl rand -base64 48
```
:::

::: tip 密钥长度按**字节**算，不是字符数
校验用的是 `configured.getBytes(StandardCharsets.UTF_8).length`。
因此 32 个汉字（UTF-8 下 96 字节）也算合格，而 31 个 ASCII 字符不合格。
:::

### 8. 管理后台 `admin`

| 配置键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `admin.username` | string | `admin` | 管理后台账号 |
| `admin.password_hash` | string | `$2a$10$njJJacGfGPEX1FHD6MB1HeKEgjfWx5zF2nrGo.gEbdjb3Q.KA3gcC` | 管理后台密码的 bcrypt 哈希 |

::: danger 默认密码是 admin123，生产环境必须更换
模板里的哈希对应默认密码 **`admin123`**，上线前请通过安装向导重新设置。

另外注意：**不要再配置明文 `admin.password`**。首次启动时明文会被自动哈希为
`admin.password_hash`，随后清除明文键。

写回是**行级值替换**，不会重排文件，也**不会丢失其它注释**：

```java
// AdminAuthFilter.java:147
// 一次性写回：写入 bcrypt 哈希，并用 null 删除旧明文键（保留文件其余注释与排版）
```

唯一被删掉的是 `admin.password` **那一行本身**，以及紧随其后、缩进更深的注释延续行
（即旧模板里对 `admin.password` 的说明注释）——这是 `YamlFileEditor` 刻意实现的语义。

::: warning 旧版本确实会丢注释
早期实现用 SnakeYAML 整文件 dump，会把注释全部丢弃并按默认排版重排。
`AppConfig` 的注释明确记为 "v2：不再用 SnakeYAML 整文件 dump（旧实现会丢弃全部注释并按默认排版重排）"。
如果你看到的是"注释全丢"的说法，那是过时描述。
:::
:::

### 15c. Buff 过期回收 `buff`

| 配置键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `buff.expire_sweep_seconds` | int | `60` | 过期增益「兜底」回收间隔（秒），**最小 10 秒**（读取时 `Math.max(10, ...)`） |

::: tip 这只是兜底，不是主通道
活跃玩家在**访问 Buff 时即时过期**，完全不依赖这个任务。兜底任务只负责离线玩家——
增益加成是物化在 `players` 表上的，玩家离线后没有触发点，属性会一直虚高。

原实现是**每秒**一次 `WHERE expire_time <= ?` 全表扫描，现已降为低频兜底。
配合 `idx_player_buffs_expire` 索引，单次代价只与"已过期的行数"相关。
首次执行延迟 30 秒，用于避开数据库初始化与启动高峰。

详见 [Buff 系统](/player/buff)。
:::

## plugins.yml

`config/plugins.yml` 的根节点是 `plugins:`，共 **30 个开关**：
24 个稳定玩法模块、2 个实验性插件、4 个消息通道适配器。

取值规则：`true` = 启用（默认），`false` = 停用（重启后生效），注释掉的行 = 使用默认值 `true`。

**取值优先级：** `config/plugins.yml` > jar 内模板 > 旧配置只读兜底
（`application.yml` 的 `built_in_plugins.*` 与 `config/experimental.yml` 的 `experimental.*`）。
