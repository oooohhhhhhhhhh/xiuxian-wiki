# 多语言（i18n）

服务端的所有**玩家可见文案**都经过语言包，不再硬编码中文。本文说明词条怎么组织、语言怎么协商、客户端该怎么接、以及新增文案时该做什么。

::: tip 一句话
代码里只留 key，中文在 `zh_cn.json`。响应同时带 `key` 和 `message`，`message` 已按本次请求的语言翻译好。
:::

## 下发的是什么

客户端拿到的是**纯译文**，不是「键+值」的原始词条表（除了显式取语言包的那一个接口）。消息体长这样：

```json
{
  "msgId": "a1b2c3",
  "type": "error",
  "code": 400,
  "key": "sect.not_member",
  "message": "你还没有加入宗门",
  "data": null
}
```

- `message` —— 已翻译的最终文案，**客户端直接显示即可**，不需要自己查表。
- `key` —— 词条键。用途是让客户端**自己再翻译一次**：它可能缓存了语言包、或想按自己的语言显示，此时用 `key` 查本地表覆盖 `message`。

为什么两个都给：服务端已经知道请求语言，翻译一次最省事；但客户端如果自己存了语言包，`key` 能省掉一次往返。两者都在，谁都不用迁就对方。

## 语言协商顺序

每个 REST 请求由 `LanguageRequestFilter` 决定用哪种语言，优先级从高到低：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | `?lang=en_us` 查询参数 | 最高优先级，便于调试与分享链接 |
| 2 | `X-Lang: en_us` 请求头 | 显式指定，客户端首选 |
| 3 | `Accept-Language: en-US,en;q=0.9` | 标准 HTTP 头，取第一个可识别的 |
| 4 | `i18n.default-language` 配置 | 服务端默认 |

识别不了的 code 会**静默跳过**，继续看下一级，不报错——老客户端传了个不认识的 `zh-Hant` 不该让请求失败。

::: warning 请求头不落库
`?lang=` / `X-Lang` / `Accept-Language` 只影响**当次请求**。想改玩家偏好必须调 `POST /game/i18n/lang`。
否则一个带旧参数的老客户端或一条被分享的链接，就能把用户偏好永久改掉。
:::

玩家偏好是**账号级**的（`players.lang`），一份设置同时作用于 QQ、Minecraft、Web 三个入口，不是按设备存的。

## 语言包的组织

词条在 `src/main/java/data/mtxgdn/lang/<code>.json`，是一个扁平的 `key → 文案` 映射：

```json
{
  "sect.not_member": "你还没有加入宗门",
  "sect.member_left": "{0} 已离开宗门【{1}】"
}
```

加载优先级从高到低：

1. 插件通过 `PluginContext` 合并进来的词条
2. 外部文件 `config/lang/<code>.json`
3. classpath 里的 `data/mtxgdn/lang/<code>.json`

外部文件覆盖 classpath，所以**改译文不用重新打包**：在 `config/lang/` 下放一份同名文件写要改的条目，调 `POST /admin/i18n/reload` 即可生效，不用重启。

回退链是 `目标语言 → zh_cn → 返回 key 本身`。`zh_cn` 是基线语言，保证任何 key 都有兜底；走到最后一步会在日志里打一条去重后的 WARN，便于发现漏翻。

## 占位符

用 `{0}` `{1}` 位置参数，**刻意不用 `MessageFormat`**——后者把单引号当特殊字符，英文文案里的 `don't`、`it's` 会被吃掉。

```java
I18n.t("sect.member_left", playerName, sect.getName())
```

写模板时的一条经验：**可空/可变的尾巴整体交给一个占位符**，不要拆成半句模板。例如季节加成写成 `开始闭关修炼（{0}，季节加成 {1}%）` 而不是 `开始闭关修炼（{0}，` + `季节加成 {1}%）`——拆开后翻译没法调整逗号位置和语序。

## 数据文件也带 key

境界配置与野外地图是数据驱动的，文案写在 JSON 里。这些文件同时提供**字面量**和 **key**：

```json
{
  "name": "青云宗",
  "nameKey": "realm.qingyun.name",
  "description": "青云宗，修真界第一大宗。",
  "descKey": "realm.qingyun.desc"
}
```

`getName()` 的逻辑是「有 key 且词条存在 → 用译文，否则用字面量」。这样老配置文件不用动就能继续跑，配了 key 才启用多语言。

## 客户端接入

### 1. 取语言包（可选）

```http
GET /game/i18n/bundle
```

免鉴权——登录页的「忘记密码」等提示也要本地化，而那时还没有 token。返回 `data.messages` 是完整的 `key → 文案` 表，`data.missingCount` 是相对基线语言还缺多少条（可用于提示「部分内容尚未翻译」）。

登录后取一次缓存即可；缓存 miss 时再补一次。

### 2. 列可用语言

```http
GET /game/i18n/languages
```

返回每种语言的 `code` / `displayName` / `keyCount` / `missingCount` / `fallbackCount`，以及服务端默认语言。直接拿去渲染语言选择器。

### 3. 读写玩家偏好

```http
GET  /game/i18n/lang      # 需要 game.i18n 权限
POST /game/i18n/lang      # 需要 game.i18n 权限
```

`GET` 同时返回 `lang`（原始值）、`resolved`（解析后含回落）、`isDefault`——客户端需要区分「没设过」和「设了个服务端不认识的」。

`POST` 传 `{"lang":"en_us"}`；传空串表示**恢复默认**（清除偏好）。

::: tip 为什么只存空串不存默认值
`players.lang` 迁移时回填的是空串而不是 `zh_cn`。这样管理员以后改 `i18n.default-language`，那些从没手动选过语言的玩家会跟着变。回填成 `zh_cn` 就永远卡住了。
:::

## 管理接口

需要 `admin.i18n.manage` 权限：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/admin/i18n/status` | 各语言词条数、缺失数、回退命中数 |
| `POST` | `/admin/i18n/export` | 导出某语言的完整词条 JSON |
| `POST` | `/admin/i18n/reload` | 重载语言包（不重启） |

`fallbackCount` 值得盯着：它表示「多少条文案实际是用基线语言顶上的」。这个数不降，说明那种语言的翻译还没补齐。

## 配置

```yaml
i18n:
  default-language: zh_cn
```

改了它只影响**没手动选过语言**的玩家（`players.lang` 为空串的那些）。

## 新增文案该怎么做

1. **别写中文字面量**。所有玩家可见文案走 `I18n.t("key", args...)`。
2. **key 命名**：`模块.含义` 的 snake_case，如 `sect.leave_leader_blocked`。
3. **加词条**：写进 `zh_cn.json`；其它语言可以后补（会回落到中文，功能不受影响）。
4. **同一句话复用同一个 key**。`你还没有加入宗门` 在 4 个端点出现，共用 `sect.not_member`——否则翻译要改 4 遍。
5. **指令的描述与用法**：在 `super(...)` 之后调 `setI18nKeys("cmd.xxx.desc", "cmd.xxx.usage")`。命令名（`names` 数组）**不翻译**，那是玩家手打的别名。

### 怎么确认没漏

```bash
node tools/i18n/find-exit-literals.js    # 消息出口里的硬编码中文，应为 0
node tools/i18n/count.js                 # A 类字面量统计
node tools/i18n/remaining-report.js      # 去重后的剩余文案，按出现次数排序
```

`remaining-report.js` 会显式排除指令注册元数据——命令名和别名本就该留在代码里。

## 相关代码

| 类 | 职责 |
| --- | --- |
| `com.mtxgdn.i18n.I18n` | 业务代码唯一入口：`t(key)` / `t(key, args...)` / `tOr(key, fallback)` |
| `com.mtxgdn.i18n.I18nManager` | 语言包加载、合并、回退、导出 |
| `com.mtxgdn.i18n.I18nContext` | 当前请求语言的 ThreadLocal |
| `com.mtxgdn.i18n.GameLanguage` | 语言枚举与 code 解析 |
| `com.mtxgdn.i18n.LanguageResolver` | 按玩家 / 用户 ID 查偏好语言 |
| `com.mtxgdn.rest.LanguageRequestFilter` | 四级协商 |
| `com.mtxgdn.rest.LanguageCleanupFilter` | 请求结束后清 ThreadLocal |

::: warning `t` 与 `tOr` 的区别
`t` 在缺 key 时**把 key 本身返回**，便于暴露漏翻译；`tOr` 返回你给的兜底文案。
凡是「缺词条不该把 key 露给玩家」的地方（如指令描述）用 `tOr`。
:::
